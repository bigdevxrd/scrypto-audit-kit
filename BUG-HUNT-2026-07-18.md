# scrypto-audit-kit — bug hunt (2026-07-18)

**Scope:** the analysis harness itself (`bin/*.py`, `audit.sh`) — not a target blueprint.
**Lens:** silent false-negatives — where the kit reports **clean** on code that contains the
very footgun a rule exists to catch. For a pre-audit tool, a missed finding is the worst failure
mode: it manufactures false confidence in code headed for a paid audit or mainnet.

**Method:** every finding below was **reproduced first-hand** by running the live code
(`bin/static_analysis.py`, `bin/sak_lib.py`) against a crafted minimal input, with a
single-line/simple **control** that fires correctly — so each is a genuine miss, not a rule that
never worked. Baseline: `python3 -m unittest discover -s tests -t .` → **131 tests green** at
commit `3879c24`.

**Summary:** 2 HIGH, 3 MEDIUM, 5 LOW. The two HIGHs and M1/M2 are the ones that most directly
turn a real vulnerability into a green report.

| # | Sev | Rule / area | One-line |
|---|-----|-------------|----------|
| H1 | High | `raw-decimal-arith` | Misses the operator when rustfmt wraps a long Decimal expression across two lines |
| H2 | High | `missing-method-auth` | One `enable_method_auth!` anywhere in a file disables the check for **every** blueprint in it |
| M1 | Med | `merge_findings` | One LLM finding suppresses **all** static siblings sharing its (class,title,severity) across distinct lines |
| M2 | Med | test coverage | The regression test for M1's bug class exercises the wrong call shape, so M1 ships green |
| M3 | Med | `// sak:allow` | A suppression leaks onto the following line, hiding a genuine adjacent finding |
| L1 | Low | `unsafe-block` | Misses `unsafe fn` and `unsafe impl` (only matches `unsafe {`) |
| L2 | Low | `todo-comment` | Blind to block-comment `/* TODO */` markers |
| L3 | Low | `float-usage` | Misses exponent-form float literals (`1e5f64`) |
| L4 | Low | file discovery | `.rs` reachable only via a symlinked dir under `src/` is silently skipped |
| L5 | Low | `unbounded-take-all` | `take(kv.get(&id).unwrap().amount())` full-drain not flagged |

## HIGH

### H1 — `raw-decimal-arith` misses rustfmt-wrapped operators
**`bin/static_analysis.py:274` (`r_raw_decimal_arith`)** uses the per-line `_matches` helper, unlike
its siblings that were migrated to whole-text `_finditer_lines` (commit `af17dc0`) specifically to
defeat newline-splitting. Raw `*` / `/` on a `Decimal` amount is the flagship Scrypto footgun
(overflow panic; `/` zero-divisor panic).

**Reproduced** (this is ordinary rustfmt output for a long expression — operator leads the
continuation line):
```rust
let v = self.vault.amount()
    * self.oracle.price;
```
→ **no finding.** The one-line form `let v = self.vault.amount() * self.oracle.price;` fires
`raw-decimal-arith`. The per-line regex sees neither `…amount() [*/]` nor `[*/] …amount()` on any
single line.

**Fix direction:** convert to `_finditer_lines` over `ctx["stripped"]`, as the other hardened
rules already are.

### H2 — `missing-method-auth` disabled for *every* blueprint if *any* blueprint in the file has `enable_method_auth!`
**`bin/static_analysis.py:259-263`** takes only the **first** `#[blueprint]` match
(`_BLUEPRINT_RE.search`) and tests `"enable_method_auth!" in s` against the **whole file**. This is
the kit's highest-severity rule (Auth bypass, high).

**Reproduced** (a normal multi-blueprint file):
```rust
#[blueprint]
mod a {
  enable_method_auth!{ methods { f => PUBLIC; } }
  struct A {} impl A { pub fn f(&self) {} }
}
#[blueprint]
mod b {                        // NO auth macro — every method PUBLIC
  struct B {} impl B { pub fn drain(&mut self) {} }
}
```
→ **no finding.** Blueprint `b` exposes an ungated `drain` and is reported **clean**. A file
containing only `b` correctly fires `missing-method-auth`. So pairing one authed blueprint with one
unauthed blueprint in the same `.rs` yields a false all-clear on the auth-bypass surface.

**Fix direction:** iterate each `#[blueprint]` span and test for `enable_method_auth!` **within that
blueprint's braces**, not the whole file.

## MEDIUM

### M1 — `merge_findings`: one LLM finding suppresses all static siblings at distinct locations
**`bin/sak_lib.py:218-244`** (culprit `if sig in primary_sigs: continue`, line 237), reached in the
default paid tier via `bin/extract-report.py` `merge_findings(llm_findings, static_findings)`.

Commit `3879c24` made *static-vs-static* dedup location-aware, but the *primary(LLM)-vs-extra(static)*
branch is still location-**independent**. The kit's own audit prompt instructs the model to reuse the
checklist class names and titles, so signature collisions with the static pass are expected by design.

**Reproduced end-to-end:** static finds `raw-decimal-arith` at `src/lib.rs:86` **and** `:98`. If the
LLM pass reports one raw-arith finding at `:86` sharing the signature, `merge_findings` drops **both**
static entries → the merged report loses `src/lib.rs:98` entirely.
```
merged locations: ['src/lib.rs:86']   # :98 silently gone
```

**Second facet (status-blind):** if the LLM marks its `:86` finding `status: false_positive`, the
merge still drops the deterministic **open** static finding and keeps only the model's
false-positive. The severity gate still trips (it counts severity regardless of status, so this is
**not** a gate bypass), but anyone filtering `status=open` — the natural "what's actually wrong?"
view — sees **zero** findings, and a non-deterministic model opinion has silently overridden a
deterministic rule the kit sells as reproducible.

**Fix direction:** when suppressing an extra against `primary`, require the **location** to match
too (mirror the static-vs-static keying), or replace only the single nearest primary rather than the
whole signature class.

### M2 — the regression test for this bug class greens while M1 is live
**`tests/test_sak_lib.py:111`** `test_full_merge_keeps_all_fixture_findings` calls
`merge_findings([], static)` — an **empty** LLM primary — and `test_merge_llm_suppresses_static_regardless_of_line`
(`:102`) uses a **single** static location. Neither exercises the production shape
(*non-empty* LLM primary + *multi-location* static), so the N:1 drop in M1 ships green. This is the
"test passes ≠ the check works" instance for the exact bug `3879c24` set out to kill.

**Fix direction:** add a case: `merge_findings([llm_at_86], [static_at_86, static_at_98])` asserting
`:98` survives.

### M3 — `// sak:allow <rule>` suppression leaks onto the following line
**`bin/static_analysis.py:314-323`** (`_suppressed`) checks `(line, line-1)`, so a suppression on
line N covers line N **and** line N+1, with no check that the "line above" is comment-only.

**Reproduced:**
```rust
self.vault.take_all(); // sak:allow unbounded-take-all
self.vault.take_all();
```
→ **no findings.** Line 2 is a genuine unbounded drain with no suppression of its own, silently
hidden because line 1 is its "line above." The auditee authors these comments (per the code's own
docstring), so this is an intentional-suppression hazard, not just an innocent misfire.

**Fix direction:** honor the "line above" form only when that line is comment-only (no code token),
so an inline suppression covers just its own line.

## LOW

- **L1 — `unsafe-block` (`:225`)** matches only `\bunsafe\s*\{`. `pub unsafe fn raw(&self){}` and
  `unsafe impl Send for V {}` → **no finding**; `unsafe { … }` fires. The rule's own rationale
  ("`unsafe` … sidesteps the safety guarantees") applies equally to `unsafe fn`/`impl`.
- **L2 — `todo-comment` (`:246`)** requires `//` syntax. `/* TODO: fix before mainnet */` → **no
  finding**; `// TODO` fires — even though the `comments_lines` view preserves block-comment bodies.
- **L3 — `float-usage` (`:161`)** literal branch has no exponent form. `1e5f64` / `1.5e3f32` → **no
  finding**; `0.05f64` fires.
- **L4 — file discovery (`analyze_package` / `os.walk`)** runs with `followlinks=False`. A `.rs`
  reachable only through a symlinked directory under `src/` is **silently skipped with no
  diagnostic** (verified: a symlinked `danger.rs` with a float literal was never scanned).
- **L5 — `unbounded-take-all` (`:187`)** the `take(<recv>.amount())` alternative matches only a
  simple dotted receiver, so a KV-store vault drain `take(self.vaults.get(&id).unwrap().amount())`
  is not flagged. (Narrow by documented design; noted for completeness.)

## Checked and working (non-findings)
CRLF / non-UTF8 (`errors="replace"`) / unicode identifiers cause no line-number drift or skips;
`enable_method_auth!` appearing only in a comment does **not** suppress `missing-method-auth` (the
stripper blanks it first); the gate/filter fail-safe on blank/unknown severity (ranks above
`critical`) and the fail-closed `collect_findings` on missing/malformed reports all behave
correctly; the `3879c24` static-vs-static fix itself is sound (M1 is the untouched sibling path).
The nonce-authentication path in `extract-report.py` (adjacency check, ambiguity refusal) held up
to inspection.

## What this bug hunt does NOT prove
Static reproduction only — no fuzzing, no property tests, and the LLM tier was not exercised live
(H2/M1's field-trigger frequency depends on real model output). The fixes above are directions, not
patches. Line numbers are against commit `3879c24`.
